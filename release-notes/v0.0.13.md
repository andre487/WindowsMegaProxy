# v0.0.13

## English

- Update downloads can be routed through the proxy probe client and CheckAsync gained an explicit download flag; installer downloads now retry on 5xx server errors (up to 4 attempts) and staged installers are verified and preserved when replacements fail.
- Updates UI separates discovery from download by showing a Download button (then Install), presents a distinct message for interrupted installations, and exposes an UpdatesThroughProxy checkbox so downloads can be performed via the engine probe profile when selected.
- Failed update checks are recorded and use exponential backoff (5, 10, 20, 40, 60 minutes cap) instead of a fixed daily interval, so successive transient failures throttle frequency automatically.
- The installer now extracts a minimal repair helper into {tmp}\repair and runs a --prepare-repair flow to close a previous installation, enabling repair even when the previously-installed helper or runtime files are missing or damaged.
- ServiceBroker exposes a Recovering state and a ConfigurationRecoveryMessage when global settings are unreadable, and the service will schedule automatic reconnect attempts with bounded backoff for transient start failures; the UI shows "Recovering connection…" and adjusts connect controls accordingly.
- Profile editor replaces the single HTTP/3 checkbox with an HTTP version selector (Stable core / HTTP/2 / HTTP/2 + HTTP/3), profiles now carry preferHttp2/preferHttp3 flags, and the runtime will prefer HTTP/2 (with HTTP/1.1 fallback) if an HTTP/3 probe signals incompatibility; this mode may require the bundled alpha core to be present.
- Podkop rules can be marked to refresh their lists through the proxy and PodkopCache supports a cacheOnly mode so refreshes can be skipped or forced to use cached copies.
- Nested ScrollViewer mouse-wheel routing is tightened so wheel events are forwarded only when the target ScrollViewer can actually scroll further, allowing outer scroll containers to receive wheel events at inner scroll boundaries.
- Documentation and UI strings were updated to reflect the new HTTP version choices, update behavior (checks vs downloads vs install), recovery messages and the UpdatesThroughProxy option.

## Русский

- Загрузки обновлений теперь можно выполнять через probe-клиент прокси и CheckAsync получил явный флаг загрузки; загрузки инсталлятора повторяются при 5xx (до 4 попыток), а подготовленные установщики верифицируются и сохраняются при ошибочной замене.
- Интерфейс обновлений разделяет обнаружение и загрузку: теперь показывается кнопка Download (затем Install), отображается отдельное сообщение о прерванной установке, а в настройках появился флажок UpdatesThroughProxy для выполнения загрузок через probe-профиль движка.
- Неудачные проверки обновлений учитываются и используют экспоненциальный бэкофф (5, 10, 20, 40, 60 минут, с ограничением), поэтому повторные временные ошибки автоматически замедляют частоту проверок.
- Установщик теперь извлекает минимальный помощник ремонта в {tmp}\repair и запускает поток --prepare-repair для закрытия предыдущей установки, что позволяет производить ремонт даже если предыдущий помощник или файлы рантайма отсутствуют или повреждены.
- ServiceBroker сообщает состояние Recovering и возвращает ConfigurationRecoveryMessage при нечитаемых глобальных настройках, а служба планирует автоматические попытки переподключения с ограниченным бэкоффом при временных ошибках запуска; в UI отображается «Recovering connection…» и элементы управления подключением адаптируются.
- Редактор профиля заменил одиночный чекбокс HTTP/3 на выбор версии HTTP (Stable core / HTTP/2 / HTTP/2 + HTTP/3); профили теперь содержат флаги preferHttp2/preferHttp3, а рантайм при несовместимости HTTP/3 будет предпочитать HTTP/2 (с откатом к HTTP/1.1); для H2/H3 режимов может требоваться включённый alpha core в поставке.
- Правила Podkop можно пометить для обновления списков через прокси, а PodkopCache поддерживает режим cacheOnly, чтобы использовать только кэшированные копии при необходимости.
- Обработка колёсика мыши в вложенных ScrollViewer ужесточена: событие прокрутки теперь перенаправляется только если целевой ScrollViewer действительно может прокручивать дальше, что позволяет внешним контейнерам получить событие на границах прокрутки внутреннего.
- Документация и строки интерфейса обновлены для отражения новых вариантов выбора HTTP-версий, поведения обновлений (проверки vs загрузки vs установка), сообщений восстановления и опции UpdatesThroughProxy.
