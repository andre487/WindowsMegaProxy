# v0.2.1

## English

- Subscription feeds can adopt an existing local profile that has the same ID during the first refresh, replacing that local profile and marking it as owned by the feed.
- If ownership metadata is missing, ApplySnapshot recovers ownership for matching profile IDs without deleting unrelated local profiles.
- Profiles that were adopted from a feed but later vanish from the feed are removed on subsequent refreshes while unrelated local profiles are preserved.
- Subscription refresh accepts an optional diagnostic log callback; the UI and ServiceBroker now supply a logger so callers can receive diagnostics.
- When a source fails during download, parse or apply, SubscriptionRefresh logs a sanitized diagnostic that identifies the source index, the failure stage (download/parse/apply) and a generic reason such as an HTTP status or "timeout" without including URLs, credentials or response bodies.
- Non-OK HTTP responses from configuration sources are now reported as HttpRequestException that carries the response status, allowing diagnostics to report concrete HTTP status codes (for example, HTTP 403) instead of a generic IO error.
- The export dialog now includes passwords and private SSH keys by default, and both kinds of credentials can be opted out by unchecking their respective boxes.

## Русский

- Подписки могут при первом обновлении принять (adopt) локальный профиль с совпадающим ID, заменив этот профиль и пометив его как принадлежащий фиду.
- Если метаданные владения отсутствуют, ApplySnapshot восстанавливает владение для совпадающих ID профилей, не удаляя при этом несвязанные локальные профили.
- Профили, принятые из фида, но затем отсутствующие в последующих версиях фида, удаляются при следующих обновлениях, при этом несвязанные локальные профили сохраняются.
- Процесс обновления подписки принимает необязательный callback для диагностических сообщений; интерфейс и ServiceBroker теперь передают логгер, чтобы получать эти диагностические записи.
- При ошибке источника во время скачивания, разбора или применения SubscriptionRefresh записывает санитизированную диагностику, указывающую индекс источника, стадию ошибки (download/parse/apply) и общее объяснение (например, HTTP-статус или «timeout»), без включения URL, учётных данных или тел ответов.
- Ответы конфигурационного источника с кодом отличным от 200 теперь выбрасывают HttpRequestException с кодом ответа, что позволяет диагностике указывать конкретный HTTP-статус (например, HTTP 403) вместо общей ошибки ввода/вывода.
- Окно экспорта по умолчанию включает пароли и приватные SSH-ключи, и оба типа учётных данных можно исключить, сняв соответствующие флажки.
