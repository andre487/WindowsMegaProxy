# v0.3.0

## English

- Installer migrated from Inno to WiX/Burn: new WiX bundle and managed bootstrapper are used and the repository rejects installing the new WiX/Burn bundle over an existing Inno installation (the installer shows an Inno-detected message and will fail if an Inno registration/uninstaller is present), so users must export settings, uninstall the old Inno installation, then install the new bundle and re-import configuration.

- Installation scope is locked per-user: only one installation scope (PerUser or PerMachine) can be registered for a given user at a time and changing scope requires uninstalling first while configuration files are preserved.

- Silent/automation CLI changed from Inno switches to Burn-style arguments and variables (examples: -quiet Scope=PerMachine Mode=service and -quiet Scope=PerUser Mode=login AutomaticUpdates=false), so automation must use the new flags and Mode/AutomaticUpdates variable values.

- Installer now fetches pinned Microsoft .NET runtime packages on-demand and verifies per-file hashes; runtime packages are downloaded only for new installs or when local runtime files are missing, damaged, or version-mismatched, and downloaded runtime files are recorded in the signed update manifest as downloaded:true.

- Early-boot (staged) updates supported for system installs: updates may stage files for replacement at boot and the worker verifies payload integrity before reboot, and a reboot is required to complete staged replacements and to allow further update/repair/uninstall actions.

- Packaged network cores no longer ship upstream sing-box EXEs; native cores are built as MegaProxy.Core.Stable.dll and MegaProxy.Core.Experimental.dll with a small signed host executable (WindowsMegaProxy.Core.exe), and packaging will reject legacy sing-box binaries when creating WiX installers.

- Managed host ⇄ native core protocol changed to a framed stdin API: the host sends two 32-bit little-endian ints (operation and configuration length) followed by configuration bytes and, for fetch operations, a length-prefixed URL; configuration is limited to 16 MiB and URL to 8 KiB and closing stdin signals core shutdown.

- Mutual Authenticode checks added: production hosts verify DLL signatures and DLLs verify their host executable before accepting commands, but the code and docs explicitly state these checks are not a security boundary and DEV builds skip signature checks (so behavior differs between production and dev builds).

- CI, tests and packaging updated: CI uploads Burn engine logs, smoke tests now expect WindowsMegaProxy.Core.* files instead of sing-box binaries and assert the new installer rejects Inno registrations and downloads runtimes only on fresh or damaged installs; legacy Inno helpers are retained under installer/legacy to rebuild older tags only.

## Русский

- Установщик мигрирован с Inno на WiX/Burn: теперь используется WiX-бандл и управляемый bootstrapper, и новый установщик явно отказывает в установке поверх существующей Inno-инсталляции (показывает сообщение об обнаружении Inno и завершает процесс), поэтому пользователям нужно экспортировать настройки, удалить старую Inno-версию, установить новый бандл и затем импортировать конфигурацию.

- Область установки фиксируется для текущего пользователя: для одного пользователя регистрируется только один режим (PerUser или PerMachine), смена области требует предварительного удаления при сохранении конфигурации.

- Команды для тихой/автоматической установки изменились с Inno-стиля на аргументы Burn/переменные (примеры: -quiet Scope=PerMachine Mode=service и -quiet Scope=PerUser Mode=login AutomaticUpdates=false), поэтому автоматизация должна использовать новые флаги и значения Mode/AutomaticUpdates.

- Установщик подтягивает указанные версии Microsoft .NET runtime по требованию и проверяет SHA-хэши для файлов; загрузка runtime происходит только при новой установке или когда локальные runtime-файлы отсутствуют, повреждены или имеют несовпадающую версию, а загруженные runtime-файлы помечаются в подписанном манифесте как downloaded:true.

- Поддерживаются staged-обновления для ранней загрузки в системной установке: файлы могут быть подготовлены для замены при перезагрузке, работник проверяет целостность перед перезагрузкой, и перезагрузка требуется для завершения замены и прежде чем инициировать новое обновление/ремонт/удаление.

- В комплекте больше не поставляются upstream sing-box EXE: сетевые ядра теперь собираются как MegaProxy.Core.Stable.dll и MegaProxy.Core.Experimental.dll и загружаются через малый подписанный хост (WindowsMegaProxy.Core.exe), а упаковка отвергает старые sing-box-бинарники при создании WiX-инсталлятора.

- Протокол взаимодействия управляемого хоста и нативного ядра заменён на фреймированный stdin: хост посылает два 32‑битных little-endian числа (операция и длина конфигурации), затем байты конфигурации и для fetch‑операции — длину + URL; ограничение размера конфигурации 16 МБ, URL — 8 КБ, и закрытие stdin сигнализирует ядру завершение работы.

- Добавлены взаимные проверки Authenticode: production-хост проверяет подпись DLL, а DLL проверяет подпись хоста перед выполнением команд, однако в коде и документации явно указано, что это не является безопасной границей, и DEV-сборки пропускают эти проверки (поведение отличается между production и dev).

- CI, тесты и упаковка обновлены: CI сохраняет логи движка Burn, smoketests ожидают WindowsMegaProxy.Core.* вместо sing-box, проверяют отказ установщика при обнаружении Inno и то, что runtime скачивается только при новом/повреждённом install; устаревшие Inno‑хелперы оставлены в installer/legacy для пересборки старых тегов.
