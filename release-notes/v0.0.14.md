# v0.0.14

## English

- Added a native HTTP/3 diagnostics helper (WindowsMegaProxy.Diagnostics.exe, GPL-3.0-or-later) and integrated it into the UI so HTTP/3 speed/latency measurements run the helper and return JSON-parsed results when the user runs a speed test.
- After a successful HTTP/3 speed test the app issues an IP reputation lookup to proxycheck.io (no API key), caches results for up to 24 hours, and displays ProxyCheck status/errors in the speed-test UI (lookup is only triggered by a completed speed test).
- Added profile-level DNS support (built-in DoH providers and CUSTOM provider) plus a separate Bootstrap DNS setting that is used to resolve proxy hostnames before connecting, and exposed both options in the new Connection settings card in Preferences.
- Enforced DNS constraints: DoH URLs must be HTTPS and must not contain query strings (ProfileDns rejects '?'); custom plain TCP/UDP DNS entries require numeric IP:port and UDP-only custom DNS requires either a SOCKS5 UDP-capable profile or HTTP/3, and the UI/strings note these limitations and validation failures.
- Added SSH Jump (SSH_JUMP) support and SSH auth-mode setting (AUTO/PASSWORD_ONLY/KEY_ONLY) in the Connection settings, and allowed entering a separate private key for the jump hop in the profile editor.
- Removed interactive host-key scanning/acceptance from the profile editor and stopped configuring host_key pinning in Windows-generated SSH outbounds (the client now accepts server host keys at runtime and exposes an ApplyKey API to save a verified key later); the README and some UI strings contain statements that are inconsistent about pin enforcement and are preserved as-is in the repository.
- Tun MTU and traffic units are now user-configurable (TunMtu validated 1280–65535, TrafficUnits = IEC or SI) and saved from the Connection settings, and the runtime includes the TunMtu value when building sing-box configuration.
- Installer/pending-update behavior changed to record installer worker PID/timestamp and to tolerate UnauthorizedAccessException when reading pending update state (reads return an "unknown" pending state if registry/process inspection is blocked), and installer smoke tests were split to require elevated GitHub-hosted runners for update suites.
- CI was reorganized into a planning step plus separate code, network and installer jobs (checkout fetch-depth: 0) and release publishing now waits for a verify-ci job that confirms a successful main CI run on the same commit before allowing publish.

## Русский

- Добавлен нативный диагностический инструмент HTTP/3 (WindowsMegaProxy.Diagnostics.exe, лицензия GPL-3.0-or-later) и интегрирован в интерфейс: при запуске теста скорости по HTTP/3 приложение запускает хелпер и разбирает его JSON-вывод.
- После успешного HTTP/3-замера приложение выполняет запрос репутации IP к proxycheck.io (API-ключ не требуется), кэширует ответ до 24 часов и показывает результат/ошибки ProxyCheck в интерфейсе скорости (запрос выполняется только после завершения теста скорости).
- Добавлена поддержка DNS на уровне профиля (встроенные DoH-провайдеры и CUSTOM) и отдельная настройка Bootstrap DNS, используемая для предварительного разрешения имён прокси перед подключением; обе опции доступны в карточке «Connection settings» в настройках.
- Наложены ограничения для DNS: DoH-URL должны быть HTTPS и не содержать строки запроса (ProfileDns отклоняет URL с '?'); пользовательские TCP/UDP‑DNS требуют числового IP:порт, а UDP‑DNS требует SOCKS5 с поддержкой UDP или HTTP/3; UI и валидация отражают эти ограничения и ошибки.
- Добавлена поддержка SSH Jump (SSH_JUMP) и режимов аутентификации SSH (AUTO/PASSWORD_ONLY/KEY_ONLY) в настройках соединения, а в редакторе профиля можно указать отдельный приватный ключ для jump‑хопа.
- Убрано интерактивное сканирование/подтверждение SSH host‑key в редакторе профиля и Windows-целевой клиент больше не записывает host_key в сгенерированные SSH‑outbound-конфиги (клиент принимает серверный ключ во время выполнения и предоставляет API ApplyKey для сохранения проверенного ключа позже); в репозитории сохранены противоречивые строки в README/UI о принудительной политике pinning.
- MTU туннеля и единицы трафика теперь настраиваются пользователем (TunMtu валидируется в диапазоне 1280–65535, TrafficUnits = IEC или SI) и сохраняются в настройках, а значение TunMtu включается в собранную sing-box конфигурацию.
- Поведение установщика/ожидаемых обновлений изменено: теперь сохраняется PID/время рабочего процесса установки и операции чтения статуса обновления устойчивы к UnauthorizedAccessException (в случае блокировки чтения возвращается состояние "unknown"), а smoke‑тесты установщика разделены и требуют elevated GitHub‑hosted раннеров для наборов, связанных с обновлениями.
- CI переорганизован: добавлен шаг планирования и отдельные job'ы для кода, сети и установщика (checkout fetch-depth: 0), а публикация релиза теперь ждёт verify-ci job, который подтверждает успешный основной CI на том же коммите перед разрешением публикации.
