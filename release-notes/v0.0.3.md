# v0.0.3

## English

- Installer and runtime: Windows Inno-based installer supports machine or current-user installs and three operating modes (manual, login task, service), preserves global and per-user data across upgrades, and can install prerequisites via WinGet; HTTP/3 core download is opt-in and verified by SHA‑256, and headless/service starts never enable HTTP/3 without explicit confirmation.
- Supported transports and limitations: profiles may be HTTPS, SOCKS5, SSH (TCP only on Windows; SSH jump and passphrase-protected private keys are not supported yet) and MASQUE/HTTP‑3 is available as experimental and requires UDP and server QUIC support.
- Updates and signing: packaging produces an ed25519-signed update-manifest.json and SHA256SUMS and will Authenticode-sign installer/update artifacts when WINDOWS_SIGNING_PFX/WINDOWS_SIGNING_PASSWORD and UPDATE_SIGNING_KEY are provided; the updater pins update-public-key.txt and verifies manifests and file hashes before use.
- CI and release automation: new workflows add Windows-focused CI and release jobs that run on windows-2025 to build signed packages and installers, validate that a pushed tag matches Directory.Build.props version, require main CI success, stage artifacts, and run final publish steps from .tools/release-automation on ubuntu-latest.
- VirusTotal gating and artifact preservation: the release job scans installer and archives via VirusTotal (35‑minute scan timeout) and preserves completed or incomplete reports as artifacts, and publication is blocked if scans report detections or remain incomplete as documented in docs/ANTIVIRUS.md.
- Release preparation and OpenAI notes: prepare-release automation can run scripts/prepare_release.py (requires RELEASE_BOT_TOKEN and optional OPENAI_API_KEY) to open a bilingual release-preparation PR and, when OpenAI is used, the generated notes are constrained to 10 bullets and 3000 characters per language as enforced by the tooling; PRIVACY.md documents use of OpenAI and VirusTotal for build artifacts only.
- Robust downloads and integrity: packaging and installer helpers include checksum-pinned core versions and code that retries on temporary HTTP 5xx errors, resolves GitHub asset endpoints as a fallback, and enforces HTTPS and trusted host/redirect checks before accepting downloaded cores or archives.
- Concrete limits and UX constraints: UI strings and docs declare concrete limits and triggers—export/import capped at 4 MiB, private key limit 64 KiB, local settings cap 8 MiB, rotating log sized 1–100 MiB—and the installer requires WinGet/OpenSSH availability for certain flows and will prompt before actions that need them.
- Localization and assets: repository now includes Russian translations (assets/strings.json), a flag set and profile color palette, toolbar/taskbar icons, samples and documentation (README.md, PRIVACY.md, docs/ANTIVIRUS.md) describing installer/update behavior and platform-specific limitations.

## Русский

- Установщик и рантайм: инсталлятор на Inno поддерживает установку для всей системы или для текущего пользователя и три режима работы (manual, login task, service), сохраняет глобальные и пользовательские данные при обновлениях и может поставить зависимости через WinGet; загрузка HTTP/3‑ядра выполняется только по явному согласию и проверяется по SHA‑256, а без интерфейса (служба/без UI) HTTP/3 не включается автоматически.
- Поддерживаемые протоколы и ограничения: профили поддерживают HTTPS, SOCKS5, SSH (только TCP на Windows; SSH jump и ключи с passphrase пока не поддерживаются) и MASQUE/HTTP‑3 как экспериментальную опцию, требующую UDP и поддержки сервера по QUIC.
- Обновления и подписи: упаковка релиза формирует ed25519-подписанный update-manifest.json и SHA256SUMS, а инсталлятор и пакеты подписываются Authenticode при наличии WINDOWS_SIGNING_PFX/WINDOWS_SIGNING_PASSWORD и UPDATE_SIGNING_KEY; обновления проверяют подпись манифеста и SHA‑256 файлов перед применением.
- CI и релизная автоматизация: добавлены Windows-ориентированные workflow, которые собирают пакеты и установщики на windows-2025, проверяют соответствие тега версии в Directory.Build.props, требуют успешного CI для main, загружают артефакты и выполняют финальную публикацию через .tools/release-automation на ubuntu-latest.
- VirusTotal и блокировка публикации: шаг релиза сканирует установщик и архивы через VirusTotal (таймаут 35 минут), сохраняет отчёты (включая незавершённые) как артефакты и блокирует публикацию при найденных обнаружениях или при незавершённом анализе, как описано в docs/ANTIVIRUS.md.
- Подготовка релиза и OpenAI: prepare-release может запускать scripts/prepare_release.py (требуется RELEASE_BOT_TOKEN, OPENAI_API_KEY опционален) для создания двуязычного PR с заметками релиза; при использовании OpenAI заметки ограничены 10 пунктами и 3000 символами на язык, а PRIVACY.md описывает использование OpenAI и VirusTotal только для артефактов сборки.
- Надёжные загрузки и целостность: инструменты сборки и инсталлятор используют зафиксированные хэши для ядер, повторяют попытки при временных HTTP 5xx, при необходимости разрешают обращаться к GitHub asset API как fallback и запрещают небезопасные редиректы/хосты перед установкой скачанных ядер или архивов.
- Конкретные ограничения и UX: строки интерфейса и документация явно указывают ограничения и триггеры — импорт/экспорт 4 МиБ, приватный ключ 64 КиБ, локальные настройки 8 МиБ, ротация логов 1–100 МиБ — и инсталлятор требует наличия WinGet/OpenSSH для соответствующих сценариев и запрашивает подтверждение перед такими действиями.
- Локализация и ресурсы: в репозитории появились русские строки интерфейса (assets/strings.json), набор флагов и цветовая палитра профилей, иконки тулбара/трея и документация (README.md, PRIVACY.md, docs/ANTIVIRUS.md) с описанием поведения установщика, обновлений и платформенных ограничений.
