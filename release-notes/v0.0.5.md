# v0.0.5

## English

- Fix service IPC for non‑elevated clients: the service pipe ACL now grants the precise client rights required so non‑elevated desktop clients can connect when their Windows account is authorized, addressing failures that left the UI unable to talk to the service.
- Show actionable read‑only diagnostics: when the client cannot authenticate or reach the service the UI now displays a distinct "Service: running, client disconnected" state and writes a detailed read‑only diagnostic (including pipe name, HRESULT and a short reason) into the local log so users and admins can troubleshoot why editing is blocked.
- Deploy self‑contained application folders instead of single‑file EXEs: production builds and the installer now publish a directory with the pinned .NET runtime files (no single‑file extraction), and the UI and service share the same runtime files in the installation folder.
- Use fixed protected installation paths: system installs live in Program Files/WindowsMegaProxy and per‑user runtimes use Program Files/WindowsMegaProxy.Users/<SID>; the installer stops the service and running clients before replacing files and validation rejects helpers outside the protected directory.
- Upgrading from v0.0.4: if the installed 0.0.4 client shows "Read-only mode" in service mode, open it once as administrator and use Settings → Application updates. The new installer fixes service access and removes legacy version directories while preserving settings.
- Post‑update cleanup and relaunch: after mode configuration the installer now starts a cleanup task that removes legacy "versions" directories once the old updater exits and (for silent update installs) attempts to reopen the updated application automatically.
- Preserve client log history during upgrade cleanup: writing the cleanup result no longer applies the default log size limit before the saved preference is loaded.
- Installer robustness and interrupted upgrades: the installer prepares existing installations by stopping the service, closes clients before file replacement, and restores the previous operating mode if preparation is interrupted.
- Release publishing retry: the GitHub release publisher now retries draft visibility with exponential backoff (and fails if the draft becomes published or remains invisible) to avoid race conditions when uploading release assets.
- UI text and export behavior tweaks: menu labels were renamed to "Import configuration…"/"Export configuration…", the invalid‑format error now reads "Invalid configuration format. Settings were not changed.", service repair instructions were clarified, and log export was made available for the local client log even when the client is in read‑only/service‑unavailable state.

## Русский

- Исправлен IPC со службой для не‑повышённых процессов: ACL канала именованной трубы теперь даёт клиентские права, необходимые для подключения, поэтому не‑повышённые десктоп‑клиенты могут подключаться при наличии прав их Windows‑аккаунта, что устраняет прежние случаи потери связи с сервисом.
- Отображение диагностик для режима «только чтение»: при невозможности аутентификации или связи с сервисом интерфейс теперь показывает отдельный статус «Service: running, client disconnected» и записывает в локальный журнал подробный диагностический текст (имя трубы, HRESULT и краткая причина) для поиска неисправностей.
- Публикация как каталоги с .NET, а не single‑file EXE: production‑сборки и установщик теперь разворачивают самодостаточную папку с закреплёнными файлами .NET (без извлечения из single‑file), причём UI и служба используют общий runtime в папке установки.
- Фиксированные защищённые пути установки: системные установки размещаются в Program Files/WindowsMegaProxy, персональные рантаймы — в Program Files/WindowsMegaProxy.Users/<SID>; установщик останавливает службу и закрывает клиенты перед заменой файлов, а проверка запрещает вспомогательные EXE вне защищённого каталога.
- Обновление с v0.0.4: если установленная версия 0.0.4 показывает «Read-only mode» в режиме службы, один раз запустите её от администратора и откройте Настройки → Обновление приложения. Новый установщик исправит доступ к службе и удалит старые каталоги версий, сохранив настройки.
- Очистка после обновления и повторный запуск: после конфигурации режима установщик запускает фоновую очистку, которая удаляет старые каталоги «versions» после завершения старого обновщика и при тихой установке пытается автоматически открыть обновлённое приложение.
- Сохранение истории клиентских логов при обновлении: запись результата очистки больше не применяет размер журнала по умолчанию до загрузки сохранённой настройки.
- Надёжность установщика и прерывание обновления: установщик готовит существующую установку, останавливая службу и закрывая клиенты до замены файлов, и восстанавливает предыдущий режим работы, если подготовка была прервана.
- Повторная попытка публикации релиза на GitHub: загрузчик релизов теперь пробует определить видимость черновика с экспоненциальной задержкой и отказывает в загрузке, если черновик стал опубликованным или остаётся невидимым, чтобы избежать гонки при выгрузке артефактов.
- Технические правки интерфейса и экспорт журналов: текст меню переименован в «Import configuration…»/«Export configuration…», сообщение об ошибке формата теперь «Invalid configuration format. Settings were not changed.», инструкции по восстановлению уточнены, а экспорт логов допускает выгрузку локального клиентского журнала в режиме только‑чтение/при отсутствии связи со службой.
