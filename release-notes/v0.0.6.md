# v0.0.6

## English

- The app now detects a running opposite channel (production vs DEV) and offers an interactive conflict dialog to either stop the other host or exit the current channel, performing the chosen action with elevation when required.
- Repeated launches no longer start a second connection: a duplicate launch activates and restores the existing window (including hidden/tray windows) and preserves the existing connection instead of creating a new one.
- A small activation handshake is implemented so a second process can request the running window to show itself and acknowledge success, and the UI respects this message without starting a new engine.
- DEV and production TUN addresses are chosen automatically from separate pools to avoid subnet conflicts with existing adapters, the chosen IPv4/IPv6 TUN addresses are logged on startup, and attempting to start when no unused private subnet remains produces a clear IOException describing the exhaustion.
- Connection startup is deduplicated and idempotent: concurrent ConnectAsync requests share the pending startup task, initiating Connect when the engine is already running immediately reports connected, and attaching to a persistent service view does not stop an existing shared engine.
- Opening diagnostics during startup is bounded so diagnostics cannot create a second engine while a connect is in progress and unexpected core exits are surfaced once and cleaned up through the normal lifecycle.
- The log viewer preserves multi-line selections and copies them with Windows CRLF line endings, and new incoming log lines do not discard an active selection or force scrolling while copying.
- A new CLI helper --resolve-channel-conflict is provided for the elevated stop/exit flow and exits non‑zero on failure while writing diagnostics when possible, so UI-initiated channel switches can escalate and report actionable errors.
- Engine startup presents clearer user-facing errors: if the other MegaProxy version is running the engine now throws an IOException instructing the user to open the application and choose which version to keep, and missing core binaries produce distinct messages for DEV vs production cases.

## Русский

- Приложение теперь обнаруживает запущенную противоположную ветку (production или DEV) и показывает диалог, предлагающий либо остановить другую версию, либо выйти из текущей, выполняя выбранное действие с повышением привилегий при необходимости.
- Повторный запуск приложения больше не создаёт второе соединение: дубликат запуска активирует и восстанавливает уже открытое окно (включая скрытые/в трей-режиме) и сохраняет текущее соединение вместо запуска нового.
- Добавлен простой протокол активации: второй процесс может запросить показ существующего окна и получить подтверждение успеха, при этом UI не запускает новый движок по этому сообщению.
- IPv4/IPv6 адреса TUN теперь выбираются автоматически из отдельных пулов для DEV и production, чтобы избежать конфликтов с существующими адаптерами; выбранные адреса логируются при запуске, а при исчерпании доступных приватных подсетей выбрасывается понятный IOException с описанием ошибки.
- Запуск соединения стал дедуплицированным и идемпотентным: параллельные вызовы ConnectAsync используют общий ожидающий таск; вызов Connect при уже запущенном движке немедленно сообщает состояние "connected"; подключение клиента к общему (persistent) движку не останавливает уже существующее соединение.
- Запуск диагностики во время старта ограничен, поэтому диагностика не может создать второй движок при выполняющемся подключении, неожиданные выходы ядра сообщаются однократно и корректно очищаются в рамках жизненного цикла.
- Просмотр журнала теперь сохраняет многострочные выделения и копирует их с Windows CRLF-разрывающими строками, при этом новые строки лога не стирают выделение и не скроллят страницу во время копирования.
- Добавлен CLI-помощник --resolve-channel-conflict для повышения привилегий при остановке/выходе другой версии; инструмент возвращает ненулевой код при ошибке и пытается записать диагностический лог для дальнейшей диагностики.
- При старте движка теперь выдаются более понятные ошибки для пользователя: если запущена другая версия MegaProxy, Start бросает IOException с указанием открыть приложение и выбрать версию, а отсутствие бинарников ядра даёт раздельные сообщения для DEV и production.
