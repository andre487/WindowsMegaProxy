# v0.2.0

## English

- Add opt-in reverse DNS for the Connections view with a Preferences checkbox and a cache-duration selector, persisted in portable configuration and validated on import (allowed values: 0, 1, 6, 12, 24, 72; default 24 hours; 0 = use DNS record TTL).
- When reverse DNS is enabled the Connections table will replace numeric IP destinations with PTR names while preserving the destination port, and responses are cached (configurable fixed duration or per-record TTL when set to 0) with a 4096-entry limit and one-hour negative caching when TTL mode is used.
- Reverse-DNS lookups are skipped for destinations that are already hostnames and are performed asynchronously during regular connections polling, updating rows in-place when resolution completes.
- Add UI controls for the reverse-DNS feature (checkbox and cache-duration dropdown) and include those settings in import/export and the service protocol so they survive configuration changes.
- Remove the negotiated proxy protocol and TLS negotiation details from the status line and tray tooltip so the window and system tray show only the application, applied profile name and profile type (tray tooltip remains limited to a single line and the platform 127-character limit).
- Give the Connections table more room for application paths by widening the application column and make protocol/upload/download columns size to header with smaller minimum widths, and render empty/inactive tables with an opaque theme background.
- Connections polling now requires the window to be active (focused) in addition to visible, which prevents background polling when the app is visible but not the active window.
- Validate the checked connection before running a speed test and show failures in a dialog and log them; speed tests are rejected if the active/applied connection changed since diagnostics were run.

## Русский

- Добавлена опциональная обратная DNS для списка соединений с переключателем в настройках и выбором срока кэша; параметры сохраняются в переносимой конфигурации и проверяются при импорте (допустимые значения: 0, 1, 6, 12, 24, 72; значение по умолчанию 24 часа; 0 = использовать TTL записи DNS).
- При включённой обратной DNS в таблице соединений числовые IP-адреса заменяются на PTR-имена с сохранением порта назначения, ответы кэшируются (фиксированная длительность или TTL записи при выборе 0) с лимитом кэша 4096 записей и часовым негативным кэшем в режиме TTL.
- PTR-запросы не выполняются для уже заданных имён хостов, а разрешение адресов происходит асинхронно в ходе обычного опроса соединений и обновляет строки таблицы по завершении запроса.
- В интерфейс добавлены элементы управления обратной DNS (флажок и выпадающий список срока кэша), параметры включены в экспорт/импорт конфигурации и в протокол службы, чтобы сохраняться при смене настроек.
- Убрано отображение согласованного протокола прокси и деталей TLS в строке состояния и в подсказке трея: теперь окно и трей показывают только приложение, применённый профиль и тип профиля (подсказка остаётся в одну строку и учитывает системный лимит в 127 символов).
- Таблица соединений получила больше места для путей приложений (шире колонка приложения), а колонки протокола/трафика теперь подстраиваются под заголовки с меньшими минимальными ширинами; пустые и неактивные таблицы визуально используют непрозрачный фон темы.
- Опрос соединений теперь требует, чтобы окно было активным (в фокусе), что предотвращает фоновый опрос при видимости приложения, но отсутствии фокуса.
- Проверка перед запуском теста скорости теперь сопоставляет запрошенные и фактически применённые настройки, а ошибки проверки или выполнения показываются в диалоговом окне и логируются; тесты скорости отклоняются при несоответствии активного соединения.
